## 为什么选 EQS

| 特性 | 说明 |
| --- | --- |
| **真正一体化** | 问卷、考试、刷题不是三个割裂的产品，题库、用户、权限、数据统一管理 |
| **零依赖部署** | 只用 Node.js 22+ 内建能力，`npm install` 都不需要，复制解压即启动 |
| **数据自己掌控** | 单文件内嵌数据库 + 本地文件存储，一个目录就是全部数据，备份=压缩一个文件夹 |

## 功能特点

**问卷与表单**
- 28+ 自定义组件，拖拽式可视化设计，支持文本 / Excel 批量导入题目
- 单行/多行文本、日期、下拉、单选、多选、文件上传、排序、级联（多级联动）、轮播、一键定位、手机号校验、矩阵量表、子表单、手写签名、评分、NPS、滑动条、分割线、富文本等
- 级联两种作答方式：层级下拉，或**搜索式选择**（输入关键字直接落到某一级，`行业分类`那种
  四级以上、几百个节点的选项树不用一层层翻；选题多时自动切换）。选项来源可以是字典、**部门树**，也可以手填
- 条件逻辑全打通：显示隐藏、动态必填、条件跳转提前结束、自动带入、公式计算、题干引用作答
  （等于/不等于/包含/大小比较/为空，多条件组合；「选了其他才必填」「没有预算就直接结束」都能拖出来）
- 表单外观配置：头图、背景图、背景色、按钮文字与颜色
- 提交后自定义文案、提交后自动跳转网址、按答卷编号查询

**发布控制**
- 按微信 / 账号 / IP / 设备限制答题次数，可要求「仅登录用户填写」（未登录在首页就换成登录入口，填完才被拒是最糟的体验）
- 定时发布：填了开始时间就到点自动开放。没到点打开链接看到的是「问卷尚未开始 · 开放时间 11-16 09:19」，
  不是「表单未发布」——那种提示会让人以为链接坏了，而且填完二十题才被拒是最糟的体验
- 访问密码、仅限微信内填写
- 记录微信昵称与头像（公众号网页授权）

**数据管理**
- 答卷新增、编辑、批量删除、筛选、标记、导入、导出（Excel / CSV / JSON）、打印
- 附件打包下载（内置 ZIP 打包，无需外部工具）
- 实时统计报表：柱状图 / 折线图 / 饼图，一键导出 PNG

**考试与刷题**
- 题库管理、Excel 导入导出（下载模板 → 填表 → 导回，形成闭环）、智能组卷、随机抽题、题目复用
- 多题库混合组卷：跨题库轮转抽题，一张卷子覆盖多个知识域，比例自动均摊
- 题目标签：文本导入写「标签：数据库,基础」、Excel 多一列「标签」、编辑弹窗直接改；
  按标签筛题、按标签组卷，筛选落空时明确报错而不是偷偷退回全库
- 题库协作：一个题库可以拉多个维护人，「可编辑」能增删改题与组卷、「只读」只能看题与刷题；
  只读身份下不下发标准答案、也导不出带答案的 Excel——不然「只读」只在界面上成立
- 正确答案、分值、答案解析、自动评分、及格判定
- 成绩排名：管理端榜单（前 N 名 + 分数分布），交卷即显示「第几名 / 超过百分之多少」；
  同分同名次、下一名跳号；公开成绩榜可选开启，名字打码，只给名次与分数
- 判分口径统一：单选/多选/判断比选项，填空比文本（忽略大小写与空格），**排序比顺序**，**矩阵逐行比**；
  交卷判分、交卷回顾、刷题判题共用同一份实现，不会出现「刷题判对、交卷判错」
- 主观题人工批阅：逐题给分、满分/0 分快捷操作、批阅备注，保存即重算总分与及格状态
- **批量阅卷**：一页十份一起批，不再「点开一份批一份」；批完的自动离开队列，
  批量保存是合并而不是覆盖——同一份卷子分两天批两题，第二天的保存不会抹掉第一天的分
- **阅卷能纯键盘走完**：数字直接填分（聚焦即全选）、`Enter` 下一题、最后一题再按一次存本页、
  `↑↓` 上下题、`Esc` 退出；留空表示「还没批」（不会被判 0 分），越界的分当场拦下并跳到那一题
- **阅卷队列按「批完会不会改结论」排**：不再只按交卷时间从头扫——队里大多数卷子批了也不改变
  任何结论（还差 5 分过线、只剩 10 分可给）。每份带一句「凭什么排在这」：
  `批完可能掉线 · 现在算过线，但这几题给不满 12 分就会掉到线下`、`批完可能上岸 · 还差 6 分过线`、
  `可能换第 1 名 · 距第 1 名 5 分`、`还没判过分`、`尺子还没定`。
  **掉线那一档排最前**：及格线按「可判分总分」的百分比算，还有 40 分主观题没批时线画在 36，
  批完抬到 60——列表上写着及格的人会翻到线下，而没人会回头追这件事是什么时候发生的。
  分数只会往上走、线也会往上走，所以「掉线」不是扣分，是线跑到前面去了。榜首只用已经批完的
  卷子算；同档按「差距 / 剩余可给分」升序，平手按 id（顺序不确定就会翻页漏人）。
  想按交卷顺序扫一遍时，一个勾切回去
- **阅卷有批次感**：弹窗顶部常驻「本次共 82 份 · 已批 37 · 还剩 45」的进度锚，
  存完接着批同一页（队列前移补位，自动翻页会漏卷）；分母只算有主观题的卷子，
  纯客观题的答卷不会让进度永远停在半路
- **批阅留痕**：谁批的、什么时候、动了哪几题、从几分改到几分、这份批了多久，一次一条。
  改分与撤分分开记（`null` ≠ 0 分）；打开看一眼就关掉不留空痕；耗时按份算不按整页算。
  答卷列表、「待批阅」与阅卷队列都直接显示批阅人——一封卷子两道题分差得离谱时，
  第一眼要看的是「是不是同一个人给的」
- **评分尺度对账**：同一道题被两位老师给出过差多远的分，一眼看得见（`6 分 vs 17 分 · 差 12 分`），
  并按满分折算成分歧程度；两两对账写着「谁平均偏松」。只数「同一份卷子的同一道题」——
  不同考生答案不同，平均分不同不算分歧
- **成绩单上的尺子**：有题目被两位老师给出不同分时，那份卷子的分数就不再是一个精确数字，
  而是带区间（`71 ≈59~71`，含义是「换另一位老师批会是这个范围」）。答卷列表、详情、
  成绩榜、导出的 Excel 都有；阅卷时那道题上直接写「尺子不一 · 张老师 12 分 · 李老师 18 分」，
  省得第三个来批的人又随手定一个口径。没被第二个人批过的题不算区间——那种预测是编的
- **批卷的人看得见自己的尺子**：尺度页上「谁平均偏松 4.6 分」是第三人称，
  而批到第 6 页的那个人不在那个页面上。阅卷弹窗顶部因此常驻一句一人称的话：
  `你比同题其他人平均高 6 分（3 处对比）`，同一道题上再单独贴一条。
  口径与尺度页的时间走向同一个回放（逐格比同题其他人的均值），所以两者不会互相打脸；
  一个人的绝对分不进这个数——「我批的这批考生答得更好」和「我的尺子松」是两件事。
  样本不到 3 处只说「先不判」，单题不到 2 处不贴；一句「你偏松」会跟着人很久，而它可能只是运气
- **批卷疲劳：一轮之内，越批越快、分越给越松**：「你比同题其他人平均高 5.3 分」是平均值——
  连着批 40 份，前 10 份认真、后 30 份照着印象给，平均下来只偏一点，而真正松掉的是后 30 份。
  阅卷弹窗顶部因此多一条：`这轮批卷 越批越快，分越来越松 · 这轮 8 份；前 3 份每份 2 分 25 秒，
  后 3 份 24 秒；同题对比 +1 → +6 分（放宽 5 分）`。相邻两条留痕间隔不超过 30 分钟算一轮，
  只比头尾各 3 份（取整场平均会把疲劳自己平均掉）。**快本身不是指控**：后面的答案可能更短、
  题更简单，所以只有「快起来的同时口径也跟着动了」才染警告色；快而稳是 `口径没动`，
  压根没有可比的分是 `口径看不出`——那是没有结论，不给颜色（绿色也是一种结论）
- **分歧结案：这处分歧按几分算，到此为止**：尺度对账能把「张老师 6 分、李老师 17 分」摆上桌，
  但它不会自己消失——只要那两笔分还在，每次刷新都是 18 处分歧、每份成绩单都挂着区间。
  教研组真实的做法是看一眼，说「这题就按 14 分算」，然后这件事到此为止：结案写一条记录、
  把分落成结论值（留痕里查得到谁拍的板），该处从悬着的分歧里消失，成绩单不再为它撑开区间。
  **过期按现在的分判断，不按时间**：后来有人把它改成别的分，这处结案就重新回到待处理
  （`stale`）；改回结论值，它自己又算定案。结案不改写历史——「当初有人给过 4 分」
  仍然算进「谁偏松」，收的只是「这条还要不要继续摆着」。撤回也留痕，不删记录
- **尺子随时间的走向**：一位老师前 20 份偏松、被谈过之后后 40 份收紧，这件事在
  「谁平均偏松 4.6 分」里看不见——平均会把两极抵消。尺度页现在按天/周/月分桶画出每个人的偏移：
  `+9 → +0.8（收紧 8.2 分）`。每个点都是「同一格上他比同格其他人高几分」，绝对分不进这条线
  （后面那批考生可能就是答得更差）；样本不足的桶不下结论，不到 1 分的变化算「没动」
- **换一把尺子重批：谁会被推出及格线**：尺度页上能按某位老师的口径把全场重算一遍——
  他真批过的那几格是把他给的分换回去（事实），他没批过的按他在那道题上的偏移平移（投影，
  单独标出格数）。结论写成人话：`8 人越线上岸 · 过线 26 → 34 人`。
  及格线本身不动（换尺子不改变题目分值），动的是人；一律剪回 `[0, 满分]`，
  超纲的分不是成绩；客观题不参与，它是机器判的；没批完的卷子不进这笔账——
  总分还会涨的卷子，它「会不会过线」是个还没定下来的数
- **换尺子之后名次会不会变**：及格线是行政上的线，教研组真正吵的常常是「按他的尺子重批，
  第一名还是不是原来那个」。分数位移了 12 分，没人能自己在心里把几十份卷子重排一遍，
  所以这里替他们排：`第 1 名换人：#11 顶替 #12`、`前 10 名有 2 人进出，最大移动 6 位`、
  或者老实的 `名次一位都没变`。名次在**全部已批完的答卷**里排（一份纯客观题的满分卷
  跟谁的尺子都无关，但它必须在榜上，否则「第 1 名换人」在真实榜单上根本没发生）；
  同分同名次照榜单的规矩；「被追平」和「并列被打散」跟「换人」分开说。
  顺序不动本身就是结论：分歧只影响分数的绝对值，不影响谁排在谁前面
- 「待批阅」筛选，只收真的还有主观题没给分的答卷（纯客观题的卷子不进队列，
  队列一有噪音老师就不看了）
- 考试防作弊：**题目乱序 / 选项乱序**（每人一份不同顺序，种子跟着答卷存，
  逐题回顾按当年那套顺序排）、**切屏检测**（计数、阈值、可超限自动交卷）；
  切屏次数只当线索不当判决——它由浏览器上报，改得动，所以只标记给阅卷人看，不据此判零分
- 顺序练习 / 随机练习 / 错题练习 / 收藏练习，答题卡、即时判题、学习笔记、练习进度
- 连续答对可自动移出错题集
- 题目收藏、学习笔记、**AI 解析**：逐题讲清为什么是这个答案、错项错在哪；
  题库里已有解析的直接读库不重复调用，AI 未配置时退回本地解析并标明来源，
  「只读」协作者问解析时不会把标准答案递给他

**平台能力**
- 用户管理、角色权限（RBAC）
- 组织架构：多级部门树（可改名、可换上级、删前校验占用）、职位挂在部门下，用户带「部门 / 职位」
- 表单协作：一份问卷 / 考试可拉多个维护人，「可编辑」能改题、发布、看数据与批阅，
  「只读」只能看表单与报表；只有所有者能管成员与删除。身份判断收敛在一处，
  列表 / 数据 / 报表 / 导出 / 附件 / 导入全部同一口径（以前 29 处各自写着 created_by）
- 模板中心：6 套内置模板，一键套用，任意表单可存为模板
- 数据字典：学历、行业、问题类型这类固定选项集中维护一份，表单「从字典取用」后一键同步；
  表单存的是**快照**而不是引用——字典改字不会静默改动一张已经收回三千份答卷的问卷
- 字典支持层级（省 / 市 / 区）：级联选择的选项也能集中维护，还能用 xlsx 导入导出，
  导出文件本身就是模板
- 部门树也能直接当选项来源：设计器里「从部门取用」，部门改一次点「同步」即更新；
  「按部门选人 / 报名」这类题不用再把组织架构手工抄一遍
- 回收中心：误删的表单、答卷、题库与题目都能恢复；彻底删除要求先入回收站，并连带清理附件文件
- 文件存储：本地 / 阿里云 OSS / 七牛云 / 又拍云 / 通用 S3
- 通知：SMTP 邮件、阿里云/腾讯云/中昱维信短信、微信公众号模板消息
- 数据同步 API（全量导出）+ WebHook 推送（新增/修改/删除，HMAC 签名）
- 第三方登录：Google OAuth、微信扫码
- 地图能力：高德地图 Key 配置用于地理题型
- 国际化：界面多语言资源可扩展，可在线编辑
- 深色模式、响应式布局，PC 与移动端皆可作答

## 快速开始

### 方式一：直接运行（推荐）

```bash
git clone https://cnb.cool/sleepyheade/EQS.git
cd EQS
bash scripts/start.sh
```

Windows 用户双击 `scripts\start.bat` 即可，脚本会自动打开浏览器。

打开 http://localhost:8080，默认账号 `admin` / `admin123`（**首次登录请立即修改密码**）。

> 需要 Node.js 22 或更高版本。没有 `npm install`，没有数据库安装，没有外部中间件。

### 方式二：Docker

```bash
docker run -d --name eqs -p 8080:8080 -v $(pwd)/data:/data eqs:latest
```

或用 compose：

```bash
docker compose up -d
```

### 方式三：Windows / 宝塔面板

- Windows：解压后双击 `scripts\start.bat`
- 宝塔：软件商店安装「Node 项目管理器」→ 添加项目 → 运行命令填 `node server/index.js`，端口 8080

## 部署到生产

```bash
# 1. 复制到服务器
scp -r EQS/ user@server:/opt/eqs

# 2. 用 systemd 托管
sudo cp deploy/eqs.service /etc/systemd/system/
sudo systemctl enable --now eqs

# 3. 配置 Nginx 反向代理（示例见 deploy/nginx.conf）
sudo cp deploy/nginx.conf /etc/nginx/conf.d/eqs.conf
sudo nginx -s reload

# 4. 打开后台 → 系统设置 → 站点 → 「客户端 IP 来源」选「信任代理头」，层数 1
#    不做这步，所有访客的 IP 都是 127.0.0.1，「每个 IP 限填一次」会变成「全站只能填一次」
```

## 备份与迁移

EQS 的所有状态都在 `data/` 目录里：`eqs.db`（数据库）和 `files/`（上传文件）。

**方式一：后台导出**
系统设置 → 系统与备份 → 导出备份，得到一个 ZIP 包；导入同一个 ZIP 当场生效（不用重启）。

- 导出是**流式**的：边读边压边发，内存不随数据量涨。几个 G 的附件目录也一样能导
- 包里带一份 `manifest.json`（版本、导出时间、各表行数、数据库 sha256），排查「这个包是什么时候的」不用解压猜
- 导入前会校验包里的 `eqs.db`：文件头、`integrity_check`、核心表齐全，通不过就当场拦下，不会拿坏库顶替
- 另外可以只读体检：拿包里的 `files` 表去对包里的条目，缺哪个附件、属于哪张表单一条条列出来（见下）
- 顶替前自动存一份快照（`data/.backups/`），页面下方「可回滚快照」一键撤回，回滚本身也能再撤回
- 单次导入上限 8GB（请求体流式落盘，不受普通接口 64MB 的限制）

**导入前先体检**

导入验的是数据库，不验附件。但备份包是人工拷来拷去的东西：断点续传一断、
网盘同步失败、`tar` 少拿一层目录，都能做出一个「库好、附件缺一半」的包——
导入时照样弹「导入成功，附件补入 0 项」，而答卷里的小抄照片、证件扫描件在没人点开之前谁都不知道它没了。

系统设置 → 系统与备份 → **体检备份**，只读地打开一次包，拿包里的 `files` 表去对包里的条目：
缺几个、缺的是哪个文件、属于哪张表单，一条条列出来。命令行同理，退出码能当闸用：

```bash
node scripts/check-backup.mjs eqs-backup-20260101-120000.zip
node scripts/check-backup.mjs backup.zip --json    # 机器可读，好包 exit 0 / 坏包 exit 1
```

**方式二：直接打包目录**

```bash
bash scripts/backup.sh          # 生成 backups/eqs-backup-<时间>.tar.gz
```

> 两种方式都会先用 SQLite 的一致性快照（`wal_checkpoint` / `VACUUM INTO`）把 WAL 里的数据落盘再打包。
> 服务运行中直接 `tar data/` 可能拿到一个没有表的空库——那是 WAL 模式的坑，不是备份成功。

**迁移到新机器**

```bash
tar -xzf eqs-backup-20250101-120000.tar.gz   # 解出 data/
bash scripts/start.sh                        # 启动即完成迁移
```

数据库换成外部 MySQL 需求可参考 `docs/architecture.md`。

## 安全边界

这几条都不影响正常使用——它们拦的是「功能对着正常浏览器一一都对、换个用法就出事」的那类情况。
前三条在「系统设置 → 站点」里可调，出厂即生效。

**跨域来源是白名单，不是反射。**
接口只对同源和你在「跨域白名单」里填的来源回 `Access-Control-Allow-Origin`，其余来源一个头都不给。
以前是「谁问就答谁」加 `Allow-Credentials`，那等于关掉同源策略——任何网页都能在访客登录状态下读走全部答卷。

**上传按真实内容判断类型。**
`.html / .svg / .xml / .js / .css` 这类「浏览器会当页面执行」的扩展名直接拒；声明成图片却是一段 HTML 的也拒；
没有扩展名但开头像网页的照样拒。存进去的文件出去时再挡一层：非图片/PDF/音视频/纯文本一律转成下载，
所有文件响应都带 `Content-Security-Policy: sandbox` 与 `nosniff`。
以前 `/api/upload` 收下一个 `.html` 就落在同源目录，`/api/files/raw/<key>` 发给管理员点开——那就是在你自己域里执行脚本。

**附件下载要鉴权，不能靠「URL 没人知道」。**
`/api/files/raw/<key>` 以前不需要任何身份：key 里有 8 字节随机数确实猜不到，但「猜不到」不等于「有权限」——
链接被转发一次、进了一次浏览器同步，答卷附件里的证件照、薪资表就永久可读，而且无法撤销。
现在两条路都得先有身份：上传接口回给你的地址带一张限期票据（匿名填表的人靠它预览自己刚传的图，6 小时、只对那一个文件有效），
其余一律要登录——管理员、上传者、该表单的协作者可以取，无关账号返回 `403`。
票据不入库：答卷里存规范路径，读取时按当前身份现签，所以导出的 Excel 和 WebHook 推出去的链接不会过期。

**升级前落库的富文本要洗一遍。**
富文本白名单是后来才有的，只在写入时生效——早先存进去的 `richtext / html` 正文没经过它，
而那些 HTML 至今仍被公开填写页渲染。升级后跑一次：

```bash
node scripts/sanitize-html.mjs           # 体检：只报告，不写库
node scripts/sanitize-html.mjs --apply   # 确认后写回（幂等，可重复跑）
```

报告会写明每一段「脏在哪」——事件属性、`javascript:` 协议、可执行标签，而不是只说「已清洗」。

**公开接口按 IP 限流。**
交卷、上传、答卷查询都不需要登录，也就没有任何成本。默认每分钟每 IP 交卷 120 次、上传 60 次、查询 120 次，
超出返回 `429` 并带 `Retry-After`（不静默丢弃）。桶按「用途 + IP + 表单」分开，一张问卷被刷不会牵连其它问卷。
登录失败锁定、每个 IP 限填一次这些原有防线不变。

## API

请求头带 `Cookie: eqs_token=…`（登录会话）或 `X-API-Key: eqs_…`（在系统设置 → API Key 创建）。

> **登录会话存在服务端**：`/api/auth/sessions` 可以列出账号登过的设备并单独踢掉其中一台，
> 退出登录会吊销服务端那一条（不只是删浏览器 Cookie），改密码 / 被重置 / 被停用会作废该账号全部会话。
>
> **API Key 只拥有签发人本人的权限**：管理员签的 Key 才是管理员级，普通用户签不了 Key。停用后立即失效。
> 这条以前写的是「等同管理员权限」，于是任何登录用户自助签一把 Key 就能导出整站数据——现在不成立了。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/auth/login` | 登录 |
| `GET` | `/api/forms` | 表单列表 |
| `POST` | `/api/forms` | 创建表单 |
| `PUT` | `/api/forms/:id` | 更新表单 |
| `POST` | `/api/forms/:id/import-text` | 文本批量导入题目，返回 `{added, droppedAnswers}` |
| `POST` | `/api/forms/:id/import-xlsx` | Excel 批量导入题目（multipart，字段 `file`） |

| `GET` | `/api/public/forms/:id` | 公开读取表单（不含答案） |

## 技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 运行时 | Node.js 22+ | 内置 `node:sqlite`、`fetch`、`WebSocket`，零依赖 |
| 数据库 | SQLite（WAL） | 单文件、无需运维、备份即复制 |
| 后端 | 原生 `node:http` + 自研路由 | 无框架开销，毫秒级冷启动 |
| 前端 | Vue 3（ESM 版）+ ECharts | 本地化引入，无构建步骤，离线可用 |
| 存储 | 本地磁盘 / OSS / 七牛 / 又拍 / S3 | 按需切换 |
